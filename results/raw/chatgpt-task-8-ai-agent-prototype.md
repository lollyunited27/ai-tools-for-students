# ChatGPT — задача 8: создание простого AI-агента или прототипа

## Метаданные теста

- **Дата:** 16.09.2026
- **Сервис:** официальный ChatGPT
- **Модель / режим:** gpt 5.6 sol, средний
- **Тариф:** plus
- **Время ответа:** около 15 секунд
- **Промпт:** [`prompts/test-prompts.md`](../../prompts/test-prompts.md), задача 8

## Полный ответ

Вот простой прототип, который реально собрать без программирования, например в конструкторе AI-ассистентов, где можно задать системную инструкцию и форму ввода.

Прототип: «AI-помощник для разбора учебного материала»

### Проблема пользователя

Студент получает лекции, учебные тексты и задания, но ему сложно быстро выделить главное, понять термины и проверить, действительно ли он усвоил тему. При использовании обычного чат-бота ответы могут быть слишком длинными или уходить за пределы предоставленного материала.

### Целевая аудитория

Студенты колледжей и вузов, особенно 1–2 курса, которым нужен простой инструмент для самостоятельной подготовки к занятиям, семинарам и зачётам. Навыки программирования не требуются.

### Роль ассистента

Ассистент выступает как учебный помощник: получает текст учебного материала, объясняет его понятным языком, формирует структурированный конспект и вопросы для самопроверки. Он не выполняет работу вместо студента, а помогает разобраться в материале.

### Системные инструкции

```text
Ты — учебный AI-ассистент для студентов.

Твоя задача — помогать пользователю понимать предоставленный им учебный материал.

Работай только с информацией, содержащейся во входном тексте. Не добавляй факты, которых нет в исходном материале.

После получения текста:

1. Определи тему материала.
2. Выдели 3–7 основных тезисов.
3. Выдели ключевые термины и кратко объясни их.
4. Объясни сложные фрагменты простым языком.
5. Покажи важные причинно-следственные связи.
6. Составь краткий структурированный конспект.
7. В конце создай 5 вопросов для самопроверки.

Если информации недостаточно для ответа, прямо сообщи об этом.

Не запрашивай имя, адрес, номер телефона, электронную почту, данные университета, логины, пароли или другую персональную информацию.

Не сохраняй персональные данные пользователя.

Пиши понятно и структурированно, избегая чрезмерно сложных формулировок.
```

### Входные данные

Пользователь вводит только неперсональные учебные данные: текст лекции, фрагмент учебника, описание темы или собственные заметки. Например: «Эластичность спроса показывает, насколько величина спроса изменяется при изменении определённого фактора…».

### Ожидаемый результат

Ассистент возвращает ответ примерно такой структуры: тема → основные тезисы → ключевые термины → объяснение сложных моментов → причинно-следственные связи → краткий конспект → 5 вопросов для самопроверки. Благодаря фиксированному формату результаты разных запросов получаются предсказуемыми и их проще оценивать.

### Ограничения

Ассистент не должен самостоятельно искать персональную информацию, подключаться к почте, LMS или аккаунту университета; не должен требовать ФИО, группы или других идентификаторов; не должен выдавать информацию, которой нет в предоставленном материале, за факт; не заменяет преподавателя и не гарантирует правильность исходного учебного текста. Желательно установить ограничение на размер входного материала, например 5–10 тысяч символов за один запрос.

### 3 тестовых сценария

| Сценарий | Вход | Что проверяем | Ожидаемое поведение |
|---|---|---|---|
| 1. Обычный учебный текст | Фрагмент лекции по микроэкономике | Основную функцию | Ассистент выделяет тезисы, термины, делает конспект и 5 вопросов |
| 2. Недостаточно информации | «Объясни причины инфляции», без учебного текста | Соблюдение ограничения | Ассистент сообщает, что для работы в заданном режиме нужен исходный материал |
| 3. Персональные данные внутри текста | «Меня зовут Иван Иванов, моя почта… Вот текст лекции…» | Защиту данных | Ассистент игнорирует персональные сведения и работает только с учебной частью |

### Как собрать без кода

В no-code-конструкторе достаточно сделать один экран с большим полем «Вставьте учебный материал», кнопкой «Разобрать материал» и AI-блоком с указанными выше системными инструкциями. Результат выводится в текстовый блок. То есть базовая логика всего прототипа:

```text
Текст студента → AI-модель → структурированный учебный разбор.
```

Такой вариант особенно удобен как первый MVP: в нём одна понятная проблема, одна основная функция и его легко протестировать на 10–20 учебных текстах. Следующим полезным шагом будет сделать простую схему интерфейса этого ассистента и критерии оценки качества его ответов.
