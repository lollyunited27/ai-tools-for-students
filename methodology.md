# Методика исследования

## 1. Цель

Сравнить AI-сервисы не по рекламным заявлениям, а по результатам выполнения одинаковых учебных задач.

## 2. Объект сравнения

Для каждого сервиса нужно зафиксировать:

- название продукта;
- модель или режим, если они явно указаны;
- дату и примерное время теста;
- используемый тариф: бесплатный или платный;
- наличие загруженного файла или веб-поиска;
- ограничения, которые повлияли на результат.

Если сервис недоступен, это записывается отдельно. Нельзя заменять реальный тест предположением.

## 3. Принцип одинаковых условий

1. Использовать один и тот же промпт для всех сервисов, если интерфейс позволяет.
2. Не исправлять ответ вручную до выставления оценки.
3. Для задач с файлами использовать один и тот же файл.
4. Для задач с источниками проверять не только наличие ссылок, но и их открываемость и соответствие утверждениям.
5. Сохранять исходный ответ или достаточно подробную запись наблюдений.
6. Если сервис запросил уточнение, сначала дать одинаковое минимальное уточнение и отметить это в наблюдениях.
7. Не публиковать личные данные, содержимое закрытых чатов и материалы с ограниченным доступом.

## 4. Шкала оценки

Оценка выставляется от 1 до 5 по каждому критерию:

- **5** — результат полностью пригоден для задачи, существенных проблем не найдено.
- **4** — хороший результат, есть небольшие недочёты, которые легко исправить.
- **3** — частично полезный результат, требуется заметная ручная доработка или проверка.
- **2** — результат с серьёзными проблемами, использовать можно только после существенной переработки.
- **1** — задача фактически не выполнена или результат вводит в заблуждение.

Оценка должна сопровождаться коротким фактическим комментарием. Например: «структура полная, но два источника не открываются», а не просто «понравилось».

## 5. Как оценивать критерии

### Качество

Насколько ответ решает поставленную задачу и подходит для дальнейшего использования студентом.

### Точность

Проверить ключевые факты по учебному материалу или надёжным источникам. Для творческих задач отметить логические ошибки и несоответствие требованиям.

### Русский язык

Оценить понимание запроса, ясность, грамматику, стиль и корректное использование терминов.

### Простота

Учесть понятность интерфейса, число обязательных шагов и необходимость специальных знаний.

### Скорость

Зафиксировать ориентировочное время до первого пригодного ответа. Не сравнивать миллисекунды: достаточно категорий «до 30 секунд», «30 секунд — 2 минуты», «более 2 минут» или точного времени, если его удобно измерить.

### Бесплатный доступ

Записать, что реально доступно без оплаты в момент теста: модель, лимиты, файлы, поиск и другие важные функции. Не ставить балл только по наличию бесплатной регистрации.

### Работа с файлами

Проверить загрузку, чтение, поиск по содержимому и корректность ответа по файлу. Если функция не тестировалась, указать «не проверено», а не выставлять догадочную оценку.

### Источники

Оценить наличие источников, их проверяемость, свежесть и соответствие утверждениям. Для сервиса без веб-поиска критерий может быть «не применимо» — это нужно объяснить.

## 6. Порядок одного теста

1. Открыть сервис и записать дату, тариф и модель/режим.
2. Вставить соответствующий промпт без дополнительных подсказок.
3. Зафиксировать ответ, время и возникшие ограничения.
4. Проверить факты и ссылки там, где это необходимо.
5. Выставить оценки по применимым критериям.
6. Записать краткий вывод: сильная сторона, слабая сторона, кому и когда подходит.

## 7. Итоговое сравнение

В `results/scores.csv` одна строка должна описывать один сервис в рамках одной задачи. Не следует механически складывать все баллы в единый рейтинг: сначала нужно сравнить сервисы по каждой задаче и учитывать их специализацию.

Если всё же рассчитывается средний балл, рядом нужно указывать:

- какие критерии вошли в расчёт;
- были ли пропуски;
- одинаково ли применялись условия;
- почему среднее значение не заменяет практическую рекомендацию.

## 8. Фиксация ограничений

В финальной версии обязательно указать дату тестирования, список реально проверенных функций, размер выборки и факторы, которые могли повлиять на результат.
